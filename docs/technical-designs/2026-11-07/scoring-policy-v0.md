# 首版候选评分策略

- 日期：2026-11-07
- 版本：scoring-policy-draft-0，未标定、未接入运行时。
- 依据：[系统契约](scoring-system.md)、[三项原设计](../2026-11-06/scope-complexity-placement.md)
- 机器可读参数：[scoring.draft.json](../../../config/scoring.draft.json)

以下数值是本轮提出的标定起点，不代表用户已确认的质量标准。
现有代码不读取该配置，不会因此开始返回数值评分。
实验引擎使用另行版本化的 [scoring.v0.json](../../../config/scoring.v0.json)，沿用本草案数值；原 draft 配置保持禁用，实际能力见[运行契约](scoring-runtime.md)。

## 1. 通用计分约定

范围为 0–100，越高越好；未知项保留区间和原因。
适用性、执行状态、判定和覆盖信息独立保存；仅 complete 的必需项形成正式 value。
内部使用未舍入值；最终展示保留两位小数，等级判定基于未舍入值。
仓库等级策略不能覆盖这些原始计分参数。

## 2. 作用域 S

| 参数 | 候选值 | 条件 |
| --- | ---: | --- |
| local 基础分 | 70 | 函数参数、函数/块内绑定，词法边界确定 |
| global 基础分 | 45 | 模块顶层、脚本全局、已确认静态共享成员 |
| verified pure 加成比例 | 20% | 函数/方法，纯度及依赖契约均已验证 |
| verified isolated-IIFE 加成比例 | 10% | 函数立即调用，隔离且无逃逸已验证 |
| verified temporary 加成比例 | 10% | 局部变量绑定，活跃区间与无逃逸已验证 |
| 属性累计比例上限 | 40% | 均以同一个基础分为基数 |

实例成员的档位仍依生命周期契约确定；import、纯类型声明不参与自产绑定评分。
同一隔离收益证据先排重，再累计比例。仅有 syntax-candidate 不满足 verified 条件。

```text
A = B × min(0.40, Σ有效且去重的属性比例)
D_raw = 2 log2(1+M) + 4 log2(1+F) + 6 log2(1+U) + 1.5L + 8W
D = min(65, D_raw)
S = clamp(B + A − D, 0, 100)
```

M/F/U 为除当前对象外、经传播规则确认的受影响方法/文件/模块的去重数量；L 为 SCC 压缩图上的最长链路；
W 为已确认的共享状态传播类别数，按状态目标及问题归属排重，不按同一赋值的执行次数重复计数。
直接/传递影响和入站/出站关系分别输出，计分只使用策略选定的影响视图。
当前文件内词法调用集合不足以形成完整 M/F/U/L/W，不能假设未知部分为 0。

若纯度未知，pure 加成范围为 `[0,0.20B]`；若链路不完整，D 范围至少保留已知下界至 65。
例如 local、其他属性已证实不适用、pure 未知且 D 确认为 0，则 S 区间为 `[70,84]`，value=null。

## 3. 复杂度 C

输入规模域、操作成本模型、时间预算和辅助空间预算必须来自任务/库契约，不能从目录或函数名猜测。
已证明的时间和空间界分别计算预算比 rT、rA；其中 r 是给定规模域上的最坏比值。

```text
PT = min(100, 20 × max(0, log2(rT)))
PA = min(100, 20 × max(0, log2(rA)))
CT = 100 − PT
CA = 100 − PA
C_regular = 0.60CT + 0.40CA
```

r≤1 时扣分为 0；零成本且预算为正时视作满足预算。零/负预算属于配置错误，不做除法或对数。
缺少预算时可输出成本表达式，对应数值子分保持未知。
固定次数、线性、对数、嵌套和递归成本按独立算法推导，禁止按循环层数直接指定分数。

严重问题的候选参数：

| 问题 | 证据要求 | 候选扣分 | C 上限 | 综合分上限 |
| --- | --- | ---: | ---: | ---: |
| 已证实死循环 | 可达路径及生命周期契约证明无界，非约定常驻循环 | 60 | 20 | 40 |
| 已证实内存/资源泄漏 | 保留/未释放链和预期生命周期违约 | 60 | 20 | 40 |

先从普通扣分中移除同一问题的重复贡献，再执行严重扣分和上限。
同一严重问题的扣分与 C 上限以一个账本贡献记录其净影响；综合上限是跨维度约束，单独保存 rawValue 和 cap。
多个不同问题可累计扣分至下界 0；同一问题的多个表现只计一次。疑似和未知不启用严重规则。

## 4. 代码位置 P

每条规则先确认对象角色、模块职责及依赖/行为证据。
候选权重如下；适用集合来自职责契约，不能直接把五条都作为所有文件的默认要求：

| 规则 | 候选权重 |
| --- | ---: |
| P-DEPENDENCY-BOUNDARY | 4 |
| P-PUBLIC-BUSINESS-COUPLING | 4 |
| P-ENTRY-CONTRACT | 3 |
| P-LEAF-RESPONSIBILITY | 3 |
| P-ROLE-MIXING | 2 |

初版规则违例强度建议使用 0（满足）或 1（已确认违例）；分级严重度另行标定后再引入。
`P = 100 × (1 − Σ适用规则(w_i×v_i)/Σ适用规则w_i)`。
适用集合为空则 not-applicable，必需规则未知则完整 P 待定。
依赖关系的次数不增加 P 扣分；只有违反职责契约时产生位置问题。

## 5. 综合与聚合

```text
G_raw = 0.45S + 0.40C + 0.15P
G = min(G_raw, 所有已生效严重问题的综合分上限)
```

缺失任一必需维度时，value=null，使用非负权重传播区间；不重新归一化已知项。
确有 N/A 的场景只产生 reduced-scope 的条件评分，不作为完整三项综合分或正式等级。
先按维度所有权聚合对象，再进行三项合成；同一贡献在祖先结果中只通过所属子结果进入一次。
默认组/文件/模块等权；具体清单、权重和分母必须随结果保存，采样结果独立标记。
下层严重问题的上限是否提升到整个模块/仓库，由风险适用范围契约决定；不能一律向全仓扩散。
没有该范围契约时，局部上限生效，祖先完整风险判定保持 pending。

## 6. 与模型及 A–E 分级的衔接

候选来源权重为 internal 60%、model 40%，前提是两路快照、规则维度和评估范围可比较。
来源先按维度融合，再做综合；相同问题不进行两次扣分求和。
若两路分差超过 15 分，记录 disagreement，暂停该维度的正式融合并进入复核。
单路有效时只展示单路结果；正式仓库等级默认要求两路都有效。
抽样覆盖与稳定性门槛待人工标定，在确定前不发布正式等级。

| 候选等级 | 分数区间 |
| --- | --- |
| A | [90,100] |
| B | [80,90) |
| C | [65,80) |
| D | [50,65) |
| E | [0,50) |

有区间但没有完整分数时，最多列 possibleGrades，不选定一个等级。
等级在本次评分完成后生成，下游从下一次运行开始使用；不形成“先降要求再提高原始分”的反馈环。

## 7. 可核算样例

以下均假定规则前提完整、没有未知证据，且只是参数演算：

1. local 函数基础分 70，pure 与 isolated-IIFE 资格已验证且收益去重，D=0：S=70×1.30=91；局部临时变量只满足 temporary 时为 77。
2. 时间成本为预算 2 倍、空间满足预算：CT=80、CA=100，C_regular=88。
3. P 只有依赖边界（权重 4，满足）与角色混用（权重 2，违例）适用：P=66.666…。
4. 三项合成：G_raw=0.45×91+0.40×88+0.15×66.666…=86.15。
5. 仅演示严重约束算术，固定 S=91、P=66.666…：C=min(88−60,20)=20，G_raw=58.95，G=min(58.95,40)=40。实际分析必须重新检查属性资格，不沿用已失效的纯度结论。
6. 保持 S=91、C=88，但 P 未知：[G_lower,G_upper]=[76.15,91.15]，value=null。

这些例子不意味着当前 AST 采集已能证明全部属性、风险或预算。
