# 复杂度评分算法

- 日期：2026-11-07
- 标识：SCP-C / complexity-evidence-1
- 状态：控制结构、分配点及本地递归候选已实现；成本求解与数值映射是后续实现规格。
- 依据：[原设计](../2026-11-06/scope-complexity-placement.md)、[采集契约](assessment-collection.md)

## 1. 输入与输出边界

输入为函数/模块执行单元、循环、分支、调用、退出位置、分配点、读写及源码证据。
函数定义与函数执行分别归属；外层循环内定义闭包不表示闭包体每次执行。
for 初始化、for-of/in 的迭代表达式归入一次求值区，条件、更新、循环体归入重复区。

当前已输出循环森林、最大语法循环深度、分支位置数、循环中调用/分配、
本地递归标记，以及模块顶层执行结构。分支位置数不是 McCabe 圈复杂度。
time.expression 和 space.expression 均为 null；循环深度不直接映射到 O(n^k)。

## 2. 时间成本中间表示

后续为每个执行单元构造带证据的成本 IR：

| IR 节点 | 成本合成 | 必需证据 |
| --- | --- | --- |
| Op | 基本操作成本或已声明契约 | 操作语义、类型及成本模型 |
| Seq(a,b) | T(a)+T(b) | 执行顺序和可达性 |
| Branch(c,a,b) | T(c)+max(T(a),T(b)) | 最坏情形分支、条件求值 |
| Loop(init,cond,step,body) | T(init)+Σ(T(cond)+T(body)+T(step))+最终条件成本 | 循环次数及退出路径 |
| Call(f,args) | 参数求值+被调函数成本 | 调用目标及输入规模映射 |
| Recurrence | T(n)=ΣT(g_i(n))+本地成本 | 递归规模变化、分支和基例 |
| Unknown(reason) | 保留已知项+unknown | 未解析目标、动态语义及缺失约束 |

if 的平均成本需要分支概率，摊还成本需要势能/聚合证明；缺失时只做有证据的最坏情形分析。
短路表达式保留条件执行；try/finally、throw、异步、生成器和隐式迭代器需单独建立 CFG。

## 3. 循环次数求解

1. 解析初始化、守卫、更新和影响守卫变量的所有写入。
2. 将输入规模绑定到声明，例如 items.length → n；名称相同不代表规模相同。
3. 固定次数循环：只有边界和步长可证明且循环体不改变边界时，得到常量次数 k。
4. 单调线性循环：求上下界和步长；检查溢出、符号、别名修改及提前退出。
5. 倍增/减半循环：在正值、严格单调和无额外更新等前提下求对数次数。
6. for-of/in：使用容器/迭代器契约；对象键数量和数组长度分别绑定规模。
7. while/do：通过不变式与变元函数推导；仅有循环语法时保留未知次数。

```text
for i < n; 然后 for j < m        → O(n + m)，在每轮体成本为常数等前提下
for i < n { for j < m {} }        → O(nm)，需要边界独立等前提
for i < n { for j < i {} }        → Σ i，求和后 O(n²)
for i < n { external(i) }          → Σ T_external(i)，目标未知时保留 unknown
```

不得根据嵌套层数机械推断指数；提前退出、不同输入维度和数据相关边界会改变结论。
同一调用点的次数属于成本计量；复用带来的影响范围归作用域项。

## 4. 递归及调用合成

使用已解析调用图求 SCC，区分直接递归、互递归和普通 DAG 调用。
对每组递归提取基例、输入变化、分支数及调用路径，构造递推式。
只有满足定理适用条件时使用主定理或其他求解规则；不能套用时保留递推式。
缓存需要缓存键、状态唯一性、命中条件和存活期证据；函数名带 memo 不证明记忆化。

当前本地循环调用图仅输出 detected-local-cycle / not-detected；后者不证明没有跨文件递归。
构造函数、方法、外部与动态目标保持 unknown，不按 O(1) 填补。

## 5. 峰值辅助空间

1. 按分配点登记对象、大小表达式、所属输入/输出/辅助空间及生命周期。
2. 建立别名、容器持有、返回和闭包关系，计算活跃对象集合。
3. 在 CFG 上合成同时存活的峰值；连续分配通常取峰值，不直接相加总分配量。
4. 循环中对象未逃逸且每轮释放可复用峰值；持续保留时结合迭代次数累计。
5. 递归空间包含栈帧大小和最大深度；尾调用优化必须有目标运行时保证。
6. 缓存、异步挂起和生成器状态分别建模，不与一次同步调用混合。

输出 `A(n,m)`、已知下界/上界、假设和 unknown 项。new、数组和对象字面量只提供分配候选，
无法涵盖字符串、内建库及隐式分配，也不能据其次数证明空间增长阶。

## 6. 终止性与泄漏

当前无条件循环只列入 termination.candidates；break、return、异常、取消与框架生命周期尚需 CFG。
存在 `while(true)` 不是死循环证明，长驻服务循环须按其退出/取消契约判定。
后续以终止变元和可达退出证明区分终止、已证实无界、疑似和未知。

泄漏判定需“持续持有/未释放”与“超过预期生命周期”两类证据：

- 结合分配、持有、释放责任、容量/淘汰契约和跨请求数据流建立保留链。
- 预期缓存、输出结果与延长生命周期的业务对象分别记录。
- 静态证据与运行观测单独标注，疑似泄漏不升级为已证实问题。

当前 memoryLeak.status 为 unknown，不以存在 new、Map 或循环分配直接扣分。

## 7. 预算与评分映射

任务配置声明输入规模域 D、允许的时间预算 BT(x)、辅助空间预算 BA(x) 及成本模型。
对可证明的界，计算最坏预算比：`rT=sup(T(x)/BT(x)), rA=sup(A(x)/BA(x)), x∈D`。
无预算可先提供成本表达式，数值子分保持待定。

建议采用单调、封顶的超预算扣分，参数经样例校准后启用：

```text
PT = min(100, kT × max(0, log2(rT)))
PA = min(100, kA × max(0, log2(rA)))
CT = 100 − PT; CA = 100 − PA
C_regular = 0.60 × CT + 0.40 × CA
C = clamp(C_regular − Σ严重问题扣分, 0, 100)
```

60/40 沿用首版权重建议；kT/kA、严重条目系数和评分上限仍待标定。
严重规则只对已证实死循环/泄漏生效；同一证据从普通超预算扣分中排除，避免重复扣分。
严重问题对综合分的约束需在校准时测试，不能依靠其他维度高分掩盖已确认问题。
