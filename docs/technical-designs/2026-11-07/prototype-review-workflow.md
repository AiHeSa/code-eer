# 原型豁免与毕业补审

- 日期：2026-11-07
- 唯一流程正文：[workflow.md](../../../prompts/contracts/workflow.md)
- 范围：补全现有两条规则的执行边界，不新增功能健康度维度或自动评估器。

## 分发

构建器将同一份 workflow.md 放入 eer-inject 与 eer-check 的 references/，两个入口先读流程再读具体规则。原生 Harness 在已有的通用规则注入中直接加入流程正文；无需依赖模型先选择 Skill。该资源进入来源和产物哈希，修改后必须重新构建／更新。

每个 Skill 保持自包含，因此各携带一份共享流程；具体质量规则仍唯一维护在 requirements/，流程不复制或修改它们。授权与豁免属于编排上下文，不注册为结构信号或新增质量规则。

## 运行记录

有明确原型豁免时，由执行代理在目标项目 `.code-eer/prompts/exemptions.json` 记录。paths 为项目相对的精确文件或目录，不隐式扩展通配符；目录包含其子项，不包含同名前缀目录。ruleIds 明确列出被跳过的现有规则，不用通配符表示全部规则。

示例仅演示记录结构，不能作为其他项目的默认豁免：

```json
{
    "format": 1,
    "exemptions": [
        {
            "id": "search-demo",
            "paths": ["experiments/search-demo/"],
            "ruleIds": ["scope-minimal-link"],
            "reason": "用户要求一次性演示，暂不审查模块组织",
            "authority": "当前任务中用户明确指定该目录为原型并豁免此规则",
            "status": "prototype",
            "history": [
                {"status": "prototype", "source": "用户原型授权", "taskId": "search-demo-task"}
            ]
        }
    ]
}
```

毕业时先更新 status 并向 history 追加触发来源、相关任务和证据引用；完成补审后保留检查范围、源码及规则版本、证据和结论引用。保留历史，不通过删除旧记录、新建 ID 或重叠 paths 恢复豁免。遇到无法确定的范围或状态按正常规则处理，并说明 unknown／partial。

账本不属于安装器的受管文件，安装器不创建、解析、重写或删除它；安装器只携带流程正文。当前没有自动引用检测、状态迁移命令或补审调度器，运行代理负责落实；生成包及 Hook 测试不证明代理一定遵循了流程。

## 状态与结论

| 状态 | 指定规则是否豁免 | 下一步 |
| --- | --- | --- |
| prototype | 是，明确范围内 | 相关任务开始／收尾核对正式引用和用户保留声明 |
| pending-review | 否 | 对原豁免代码及正式接入边界补审，证据不足保留此状态 |
| reviewed | 否 | 补审已完成，问题结论独立保存，后续改动照常审查 |

豁免是 exempted，不能当作 clear／satisfied；有跳过项的整体覆盖保持 partial。补审不局限于毕业时的 diff，缺旧基线仍为 unknown，不通过空差分销账。用户同意大改仅记录实施授权，不产生上述任何豁免。

## 验证范围

集成测试验证流程完整进入两个 Skill 及两种原生包、修改导致哈希失效、缺失或篡改资源会报错，以及安装／更新／卸载保留账本。模型是否识别真实毕业事件、补审结论是否正确属于实际执行证据，不由这些打包测试宣称通过。
