# 评分标定与实施顺序

- 日期：2026-11-07
- 依据：[系统设计](scoring-system.md)、[候选参数](scoring-policy-v0.md)
- 状态：计划；现有测试只证明采集/运行行为，不证明数值评分质量。

## 1. 标定集合

建立独立样例清单，按语言、框架、对象类别、规模和职责角色分层。
同一类场景同时准备质量较好、质量较差、事实不足三种输入。
人工先给相对排序、严重问题标记和理由，再用候选参数计算，避免让候选公式反过来定义“正确答案”。
用于调参的样例与保留验收集分开。对外发布的策略记录样例集摘要、专家分歧及未覆盖语言。

## 2. 核心样例矩阵

| 组 | 输入变化 | 验收重点 |
| --- | --- | --- |
| S-LOCALITY | 同一行为移入局部或暴露为共享状态 | 档位及状态证据改变可追溯 |
| S-PURITY | 本地纯计算、参数属性写、动态调用 | verified、impure、unknown 不混用 |
| S-IIFE | 无逃逸 IIFE 与返回闭包/启动异步任务 | 立即调用与隔离资格分开 |
| S-LIFETIME | 短期变量、容器持有、闭包捕获 | 不以词法范围代替存活期 |
| S-IMPACT | 单调用方、多模块复用、递归、截断 | 对象去重、SCC 链路及下界 |
| C-SEQUENCE | 连续 n/m 循环与独立嵌套循环 | O(n+m) 和 O(nm) 由证据推导 |
| C-BOUNDS | 固定循环、倍增、数据相关边界 | 常量/对数/未知不靠深度猜测 |
| C-RECURSION | 线性递归、互递归、记忆化 | 基例、状态数、调用栈及缓存 |
| C-MEMORY | 每轮临时对象与跨请求持续保留 | 分配量、峰值及泄漏分别判定 |
| C-SEVERE | 已证实死循环、常驻服务、疑似泄漏 | 只有已证实且违约的问题启用严重规则 |
| P-ROLES | 公共叶子、业务入口、混合职责 | 显式模块契约及角色适配 |
| P-BOUNDARY | 合法复用与禁止的反向依赖 | 只计职责违约，不重复计复用规模 |
| MISSING | 无预算、无契约、动态目标、后端不可用 | 不生成完整分数或正式等级 |

## 3. 不变量与性质测试

- 相同事实、清单、规则及参数下，internal 结果及贡献顺序一致。
- 仅改变仓库等级时，原始 S/C/P 与综合分不变。
- 同一证据重复到达、调用图成环、路径重命名时，不增加重复扣分。
- 同一个问题不同时进入普通与严重扣分，也不跨维度重复归属。
- 未知项增加时，不凭空生成完整高分；值必须落在可证明的区间中。
- 聚合结果的分母与清单对应，未采集对象不会从分母静默消失。
- 候选叶子、语法纯度候选、零已知引用不会直接成为已验证质量结论。
- 提高已确认预算违约程度时，复杂度分不升高；减少职责违例时，位置分不降低。
- 权重变化只影响合成，不修改已有事实、子规则判定或证据归属。
- 来源分差、快照不一致、规则版本不一致时，正式融合按策略阻止。

## 4. 参数敏感性与发布门槛

对基础分、属性比例、链路系数、严重扣分、角色权重及等级阈值分别扫描。
检查人工排序一致性、正反例间隔、严重问题上限、未知项比例以及各参数对结果的影响。
不能只看平均拟合误差；同时记录各语言/角色的误报、漏报与无法判定比例。

发布门槛先以可检查条件定义：

1. 必需规则有独立正例、反例和未知例，且没有候选冒充证明。
2. 所有不变量通过；贡献账本能重算结果，保存分数与重算分数一致。
3. 人工保留集的排序、严重问题和分歧标准达成约定，再固定数值阈值。
4. 声明支持的语言和框架分别验收，不将 JS/TS 通过自动推广到其他语言。
5. 评分策略从 design-only 升级为 validated 的操作独立记录；当前配置仍不可用于正式出分。

## 5. 实施里程碑

| 阶段 | 交付 | 完成依据 |
| --- | --- | --- |
| A 契约与纯计算 | 规则/结果 Schema、版本、参数校验、区间与合成函数、排重账本 | 构造证据上的算术与不变量测试 |
| B 作用域 | 项目绑定、引用/调用图、纯度摘要、逃逸与影响分析 | 各属性与链路的证明/未知用例 |
| C 复杂度 | CFG、成本 IR、循环/递归/空间求解、任务预算及严重问题 | 表达式及条件的独立对照 |
| D 代码位置 | 模块职责契约、跨文件依赖、角色与适配规则 | 不依赖目录命名的职责验收 |
| E 标定与合成 | 人工排序、参数扫描、聚合和模型融合、可选 A–E | 保留集、不变量、覆盖与来源审计 |
| F 服务接入 | 正式评分服务接口与结果存储 | 请求生命周期、取消、快照及重放 |

本轮开始于系统设计；当前后台只提供 AST 与证据采集，未提前开放正式评分接口。
