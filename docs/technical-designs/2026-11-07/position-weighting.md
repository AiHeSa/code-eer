# 位置关联加权评分 v1

- 日期：2026-11-07
- 需求：[REQ-SCP-002](../../requirements/code-review/position-conditioned-weighting.md)
- 策略：[scoring-policy-v1](../../../config/scoring.v1.json)，引擎 scoring-engine-2。
- 状态：已实现并接入后台服务；系数为实验值，尚未经过人工样本质量标定。

## 1. 评分原则

叶子承担末端工作，不因未写成纯函数、IIFE 或额外封装而降低作用域分；叶子的有效 S 只评估影响链路深度。
中间承接、共享全局、入口和公共模块承担更大的结构责任，保留原有作用域要求，并提高普通质量问题的扣分及汇总贡献。
位置上下文参与 S/C 计算，不将 P 的数值乘到 S/C，也不创建同一问题的第二份扣分。
叶子依然评估执行成本和严重风险；“只看链路深度”针对 S 的封装要求，不等于免除 C 的检查。

## 2. 位置识别与优先级

| 位置来源 | 生效依据 |
| --- | --- |
| 文件职责 | `configuration.positions: [{path, role}]`，path 为项目相对 glob |
| 函数职责 | 既有 responsibilities 的文件 glob、函数名、leaf/entry/intermediate |
| 公共模块 | modules 中显式配置 kind=public |
| 入口文件 | modules.entries 中的项目相对文件路径 |
| 全局文件 | 脚本 global 作用域，或模块顶层 let/var、导出的非函数/非类状态声明 |
| 中间承接函数 | 存在已解析的本地或直接导入函数调用出边；递归也属于此类 |
| 叶子函数 | 完整细粒度语法、存在执行体，且本函数没有 call/new 调用；允许副作用 |

纯目录名、文件名或“零已解析出边”不能证明叶子。存在未解析调用、构造调用或仅结构级事实时，保留未知角色。
显式 leaf 契约也不能绕过上述拓扑前提；其他严格职责可由配置明确指定。
文件角色由其函数和局部绑定继承；模块所有的绑定与初始化至少使用 global 要求。
同一函数还可以同时继承入口、公共和全局等职责：取各项系数最大值，不将多个系数连乘。
严格文件中的叶子函数沿用文件的严格要求；未知角色对所有候选配置取数值包络，并保持 partial。

## 3. 默认权重矩阵

| 位置 | S 扣分系数 | C 普通扣分系数 | 汇总重要性 |
| --- | ---: | ---: | ---: |
| leaf | 0.5（仅作用于链路深度） | 0.5 | 1 |
| intermediate | 1.25 | 1.25 | 1.5 |
| global | 1.5 | 1.5 | 2 |
| entry | 1.5 | 1.5 | 2 |
| public | 1.5 | 1.5 | 2 |

矩阵、角色冲突策略、未知策略及叶子深度系数均绑定 position-weights-v1。
Schema 要求中间/全局/入口/公共位置的每项系数严格大于叶子；严格位置的系数不得小于 1。
修改配置后 manifest 的 policyDigest 改变；历史 v0 文件与历史报告保持原内容。

## 4. 作用域计算

先用 v0 规则计算基础分 S₀，并完整保留基础分及其状态。

```text
叶子：S = clamp(100 - 1.5 × w_scope(leaf) × L, 0, 100)
严格位置：S = clamp(100 - w_scope(role) × (100 - S₀), 0, 100)
```

L 是反向调用图中从当前对象到最远已知调用者的链路深度，按调用边计数；不是已证明的运行时调用栈长度。
模块初始化直接调用也记一条边。递归 SCC 不凭压缩后深度判定有限；调用者中存在环、外部暴露、别名或截断时保留深度区间。
若只能证明深度下界 Lₘᵢₙ，叶子 S 区间为 `[0, clamp(100 - 0.75 × Lₘᵢₙ)]`，不发布确定分。
深度的完整性独立于纯度证明，因此带副作用的封闭叶子也能得到确定 S。
叶子的基础封装规则仅供审计，标记 not-applicable，不进入有效 S 的完成度或未知原因统计。
局部绑定继承其所有者函数位置；其链路取现有引用根的反向深度。

## 5. 复杂度计算及严重约束

```text
d_time = clamp(20 × w_complexity(role) × max(0, log2(T / B_time)), 0, 100)
d_space = clamp(20 × w_complexity(role) × max(0, log2(A / B_space)), 0, 100)
C_regular = 0.6 × (100 - d_time) + 0.4 × (100 - d_space)
```

同一成本事实、同一预算下，叶子普通扣分较小，严格位置较大。
显式任务预算、成本上界与精确值的区别、风险覆盖要求均沿用 v0。预算或证明缺失仍为 partial。
再对 C_regular 应用原有严重问题扣分、去重与维度封顶；严重扣分 60、维度封顶 20、综合封顶 40 不乘位置系数。
严重综合封顶取最小值向文件、模块和仓库传播；传播责任未确定时同时保留 partial，不被大量叶子稀释。
来源分歧也不能丢弃已确认的严重封顶。

## 6. 汇总与报告

所有权组内、文件内、模块内及仓库内的 S/C 使用显式重要性加权均值，P 仍按原有规则汇总。
上一级重要性继承成员重要性的最大值；未知角色使用候选重要性的最大值，并保留评分不完整状态。
加权均值不删除未知、失败或不适用项，不按已知项重新归一化；既有分组防止按变量数量直接增加整个函数的重要性。
重要性改变的是各对象的贡献比例，不重复登记问题。
三项合成仍为 `0.45S + 0.40C + 0.15P`；双来源等级条件保持不变。

每个对象的 S/C details 保存：

- baseline：未加权分、区间、覆盖度与基础规则标识。
- positionWeighting.context：角色、候选、确定性、证据 ID 和采用理由。
- positionWeighting.profiles：实际采用的扣分系数与重要性。
- positionWeighting.version、aggregationWeight，以及有效分计算信息。

manifest 保存策略、配置和位置上下文摘要；internal/model 合成 v1 分数时必须同时匹配这些摘要与源码快照。
目前仍只执行 internal，未接入模型提供者。使用旧 v0 策略仍可运行基础映射，不覆盖历史结果。

## 7. 验证范围与限制

测试覆盖固定事实切换角色、带副作用叶子、局部绑定继承、模块初始化链路、直接跨文件调用、
未知调用、递归调用者、多角色、共享状态、入口契约、预算缺失、汇总重要性和严重封顶传播。
自动角色识别基于当前 AST/直接调用图能力；动态分派、重导出链、外部消费者和其他语言的细粒度语义仍可能未知。
本轮不把语法链路长度当作时间复杂度，也不把拓扑叶子等同于业务职责已完整证明。
