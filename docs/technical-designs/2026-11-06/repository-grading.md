## 1. 已确认约定

仓库等级由模型随机抽样评估和 internal 确定性抽样评估综合得出。等级为 A–E，A 健康度最高且要求更严格，E 健康度最低且适当放宽限制。原始评分使用统一标准。

分级结果作为其他功能的可选依赖。后续 internal 功能及提示词工程功能产出各自对应评分。

以下内容为实现前的设计建议。

## 2. 处理流程

```text
仓库源码快照与评估配置
        ↓
候选范围、入口及功能分支识别
        ↓
模型分层随机抽样       internal 确定性抽样
        ↓                         ↓
提示词评分                   代码规则评分
        └─────────┬───────────────┘
                  ↓
         有效性与覆盖范围检查
                  ↓
          评分合成及 A–E 分级
                  ↓
       后续功能选择等级对应限制
```

分级评估自身使用固定评分配置。后续功能在执行前绑定已有分级结果和策略版本。

## 3. 职责划分

| 职责 | 处理内容 |
| --- | --- |
| 范围识别 | 仓库快照、文件范围、语言、框架、模块、入口及功能单元 |
| 抽样 | 候选集合、选择方式、种子、排序、去重、样本清单与覆盖统计 |
| 模型评估 | 评分提示词、模型调用、结果校验、维度评分和证据 |
| internal 评估 | 确定性规则计算、维度评分、证据和未执行项 |
| 综合分级 | 有效性、维度及来源合成、等级映射 |
| 等级策略 | 分级结果读取、有效性判断、限制选择和默认策略 |

模型提示词中的评分条目与 internal 的评分条目通过稳定标识关联。重复覆盖的维度保留来源，具体合成和计分规则待确定。

## 4. 抽样约定

模型抽样记录候选集合和随机种子，保存实际选取的文件或功能单元。模型运行记录模型版本、参数、评分提示词版本、输入摘要及实际响应。固定抽样配置可复现样本集合，模型评分稳定性单独评估。

internal 抽样使用固定入口类型、功能分支识别方式和选择规则。候选范围、顺序、评分规则及输入均相同时，评分结果应一致。

代码入口可涉及可执行程序、包导出、服务路由和框架入口，支持种类待确定。功能叶子定义依赖所选功能关系；跨文件调用关系、动态入口和未解析关系分别记录能力状态。

当前 AST 提供声明、模块、导入导出和框架结构事实；项目级符号与跨文件调用关系需按对应能力接入和验收。

## 5. 建议结果信息

| 信息 | 内容 |
| --- | --- |
| 仓库与输入 | 仓库标识、提交版本、工作区内容摘要、分析范围 |
| 评分版本 | 维度、规则、提示词、合成及等级映射版本 |
| 两路评分 | 各维度分数、适用范围、有效性、错误和未执行项 |
| 样本记录 | 候选范围、抽样配置、实际清单、样本与源码位置 |
| 覆盖信息 | 已评估范围、未支持范围、失败范围及不足项 |
| 综合结果 | 综合分数、A–E 等级、来源评分及合成依据 |
| 消费策略 | 使用的已有评估结果、等级、限制配置、默认策略及原因 |

分数字段、状态及合成方式在评分体系确认后形成可执行 Schema。

## 6. 复用与可选依赖

下游功能可选择使用仓库等级，也可使用通用默认限制。消费时记录实际采用的策略和分级来源。

仓库健康度的原始评分和下游功能执行限制分别维护。各功能只调整已声明为可配置的限制项。等级变化对原始评分口径的影响由一致性用例校验。

分级结果的输入摘要和规则版本用于有效性判断。单路有效、样本不足、仓库增量变化及重评频率的策略待确认。

## 7. 能力组织

通用抽样、评分、合成和策略入口由对应通用文件定义。语言、框架专项按 `xx.java.ts`、`xx.go.md` 等约定组织；专项公开入口为通用入口的子集，缺项使用通用实现。

功能实现与评分提示词按职责维护；需求、评分方法、实现及验证用例通过稳定标识关联。
