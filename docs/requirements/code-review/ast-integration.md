- 需求编号：REQ-AST-001
- 创建日期：2026-11-06

## 1. 目标

为代码健康度评估与代码质量审查提供语言原生的解析、结构提取及可扩展的语义分析能力。

首批支持五个语言方向：JS/TS、Python、Java、Go、Rust。JS 与 TS 共用一个后端，但需分别验证。每个后端可以独立安装、启用和验证，通过共同接口供本项目使用。

## 2. 已确认范围

| 语言方向 | 文件范围 | 首批共同交付能力 | 进一步接入的能力 |
| --- | --- | --- | --- |
| JS/TS | `.js`、`.mjs`、`.cjs`、`.jsx`、`.ts`、`.mts`、`.cts`、`.tsx`；声明文件按项目配置处理 | 解析、结构和导入导出提取、诊断；采用新版 TypeScript 接口 | 结合项目配置查询类型与符号 |
| Python | `.py`、`.pyi` | 解析、结构与导入提取、语法诊断 | 作用域和限定名称元数据；格式保留的修改能力按需增加 |
| Java | `.java` | 解析、声明和导入提取、语法诊断 | 在源码路径与依赖齐备时解析符号、方法与类型 |
| Go | `.go`，区分普通源码与测试文件 | 解析、声明和导入提取、语法诊断 | 结合模块、构建标签和平台配置进行包加载与类型分析 |
| Rust | `.rs`，识别 Cargo 项目与 workspace | 解析、声明与 use/mod 提取、语法诊断 | 按需查询定义、引用和类型；需独立验证宏与 cfg 的分析范围 |

“共同交付能力”是五个方向都必须完成的验收基线。“进一步接入的能力”按各后端能力实现并单独标注状态，不要求五种语言具有完全相同的语义能力。

本轮只确定首批单语言能力，不要求跨语言调用关系、跨语言数据流、完整污点分析或统一所有语言的 AST 节点模型。ast-grep / Tree-sitter 保留为调研候选，不作为首批必需依赖。

## 3. 功能要求

### AST-F01：独立后端与环境识别

- 每个语言方向可单独启用；未安装其他语言环境不影响已启用的后端。
- 可查询后端版本、目标语法版本、可用能力及缺失的运行环境。
- 区分工具运行时版本、被审查代码的语言版本与项目构建配置。
- JS/TS 采用新版 TypeScript API 路线；不以旧版 API 兼容作为首批目标。

### AST-F02：文件与项目分析

- 支持指定文件、文件列表和项目根目录；首批以磁盘上的源码为输入。
- 依据显式语言、文件扩展名和项目配置选择后端；混合仓库可分别分析不同语言，但不推定跨语言语义。
- 支持包含、排除路径及测试文件开关；第三方依赖和构建产物默认不作为被审查源码。
- 保留项目所需的依赖信息供类型或符号解析使用；“不审查依赖源码”不等于“禁止解析依赖”。

### AST-F03：结构事实与诊断

- 提取当前语言适用的函数、类型、方法、模块及导入导出等事实，保留源码位置和语言专属信息。
- 返回解析诊断；具备语义能力时可返回类型诊断和符号信息。
- 首批语法后端不要求提供完整调用图、类型推断或自动修复。
- 审查规则在独立需求中逐项定义；本轮验证数据能被审查代码消费，不预先制定整套规则或健康度评分。

### AST-F04：能力与完整性必须可辨识

- 明确区分完成、部分完成、失败和取消。
- 依赖缺失、语法版本不支持、解析失败、语义分析不可用、超时等情况必须可识别。
- 语义能力不可用时，可以保留有效的语法结果；依赖语义的规则应标记未执行及原因。
- 空的问题列表不能单独表示“健康”或“全部检查通过”；需同时返回完成状态、诊断、错误和未执行项。

### AST-F05：统一调用与输出

- CLI、MCP、前端工作台通过核心模块复用同一组语言后端。
- 调用结果应能追溯输入文件、后端版本、语言版本、配置和所执行的能力。
- 对外统一必要的结构事实、诊断与位置，不直接要求各语言输出相同的原生 AST。
- 审查问题、编译器诊断和工具运行错误分开表达。

### AST-F06：执行与隔离

- 支持超时、取消和单个后端故障隔离。
- 语法解析以读取源码为主；项目构建脚本、Rust build.rs / 过程宏等执行行为需通过明确的运行配置控制。
- 缺少依赖时报告受限能力；依赖下载和构建流程与源码解析分开配置。

### AST-F07：版本与验证记录

- 集成时锁定实际验证的工具、库和运行时版本，记录支持的语法与项目配置范围。
- JS/TS 的新 API 验证需先完成小型验证项目，再开展完整接入。
- 预发布版本应标注版本与状态；升级后运行相关兼容性用例。

## 4. 验收标准

- 五个语言方向均可独立完成“读取源码 → 解析 → 输出结构事实与诊断”。
- JS 与 TS 分别覆盖普通模块及 JSX / TSX 用例；新语法按锁定版本建立用例。
- 每种语言覆盖正常源码、语法错误、文件缺失、配置或依赖缺失，以及非 ASCII 源码位置。
- 结构结果保留足够信息供后续编写审查规则，且能够定位回原始源码。
- 请求不支持的能力时，明确返回原因；不把未执行规则视为通过。
- 具备语义能力的后端使用跨文件样例验证符号或类型查询；语法后端不得伪造此类结果。
- 单个后端不可用、崩溃或超时，不影响其他已启用后端的分析。
- 每个后端有可重复的运行说明和兼容性记录。
