## 1. 已确认的功能定位

对当前被审查仓库进行代码健康度评估，综合模型评估与 internal 评估，将仓库划分为 A、B、C、D、E 五个等级。

仓库分级评估是其他功能的可选依赖。后续 internal 实现的功能和提示词工程中的功能均产出对应评分，并可根据仓库已有健康度等级调整限制。

| 等级方向 | 使用约定 |
| --- | --- |
| A | 健康度最高，使用更严格的要求 |
| B、C、D | 按已确定的等级策略执行，具体限制待定义 |
| E | 健康度最低，适当放宽要求 |

原始评分使用统一标准。仓库等级影响执行时采用的限制，原始分数保持同一评价口径。

## 2. 已确认的评估方式

### 模型评估

- 参照提示词中定义的评分方法，对当前仓库的随机部分进行评分。
- 评估要求、评分方法和适用范围由提示词工程维护。
- 模型评估结果参与仓库综合分级。

### internal 评估

- 按代码实现的逻辑进行确定性评分。
- 抽取代码库入口及不同叶子节点的功能分支作为评估对象。
- internal 评估结果参与仓库综合分级。

### 综合分级

- 综合两种评估的评分形成仓库健康度等级。
- 保留两路评分及其评估范围。
- 综合权重、分数范围及 A–E 的分界线待确定。

## 3. 补充设计建议

以下条目作为待确认的设计建议记录。

### 评分与执行策略

- 统一评分契约放在功能出口；功能内部的 AST、协议、文件读取及辅助计算向所属功能提供事实。
- 每个评分保留评价维度、评分标准版本、证据、执行状态和适用范围。
- 分级评估使用固定版本的评分标准；其他功能记录执行前选定的等级及限制配置。
- 评分标准与按等级调整的执行限制分别记录。相同事实和评分标准版本下，仅改变仓库等级时，原始分数保持一致。
- 功能依赖的等级结果在本次执行前固定；新生成的等级在后续执行中使用。

### 抽样与范围

- 模型抽样记录候选集合、随机种子、实际样本及来源快照。
- 抽样可按语言、框架、模块和规模分层；抽样单位、数量及比例待确定。
- internal 抽样固定入口识别规则、分支选择规则、排序及去重方式。
- 叶子节点按功能关系定义，具体末端功能单元及识别方式待确定。
- 抽样结果标注实际覆盖范围；样本评分随覆盖信息参与综合分级。

### 缺失、失效与使用

- 没有可用分级结果时，其他功能使用通用默认限制，并记录所用策略。
- 模型不可用、能力不足、样本不足和解析失败分别记录；未完成的评估保留状态和原因。
- 完整综合分级要求两路评分满足有效性条件；单路有效时的临时结果策略待确定。
- 分级结果绑定仓库版本、输入摘要及评分标准版本；仓库变化后的复用与失效条件待确定。
- 单次抽样评估的覆盖程度、模型评分稳定性与确定性计算的可复现性分别记录。

### 语言与框架专项

- 抽样、评分、合成及等级策略均定义通用入口。
- 语言和框架专项遵守通用入口及评分结果契约。
- 专项缺项使用通用实现，公开入口范围由提交前继承校验约束。

## 4. 待确定事项

| 事项 | 待确定内容 |
| --- | --- |
| 评分体系 | 评分维度、分数范围、扣分或加分规则及版本约定 |
| 两路合成 | 各维度权重、两路权重、重叠证据处理、显著分歧处理 |
| 等级划分 | A–E 分界线及是否采用特定维度的等级约束 |
| 模型抽样 | 抽样单位、分层、比例、数量、重评及结果稳定性要求 |
| internal 抽样 | 入口类型、功能叶子定义、分支识别与选择方式 |
| 等级策略 | 各功能允许调整的限制、调整范围及配置方式 |
| 结果有效性 | 单路结果使用、样本不足、复用范围、失效与重评条件 |

## 5. 建议验收标准

- 模型与 internal 两路结果均可追溯评分方法、样本、仓库快照和证据。
- 相同输入、规则版本和抽样配置下，internal 抽样与评分结果一致。
- 模型抽样可复现，模型调用版本、输入及实际评分结果被记录。
- 同一原始评分在不同等级策略下保持统一口径，并能查看实际采用的限制。
- 下游功能在分级缺失或失效时执行约定的默认策略。
- 无效或未完成的评估具有可辨识状态；有效等级仅使用 A–E。
- 通用与专项功能的缺项回退、入口范围及结果契约通过相应校验。
