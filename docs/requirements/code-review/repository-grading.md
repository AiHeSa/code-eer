## 1. 已确认的功能定位

对当前被审查的代码仓库进行整体健康度评估，综合**模型评估（LLM）**与**内置算法评估（internal）**两路评分结果，将仓库健康度划分为 **A、B、C、D、E** 五个等级。

- **作为下游功能的可选前置输入**：仓库分级评估是其他审查与评估功能的可选依赖。后续无论是内置算法实现的确定性功能（internal），还是基于提示词工程（Prompt Engineering）的模型评估功能，都会产出各自的评分，并可根据仓库当前的健康度等级动态调整执行时的限制策略（如准入阈值或检查严苛度）。
- **原始评分与执行限制解耦**：各评估功能的**原始评分**始终采用统一的客观标准计算；仓库的 A–E 等级仅决定下游执行时采用的**限制宽严度**，不会反向改变原始分数的评价口径。

| 仓库等级 | 健康度水平 | 下游执行策略约定 |
| --- | --- | --- |
| **A** | 健康度最高 | 采用更严格的质量要求与执行限制 |
| **B、C、D** | 中等过渡区间 | 按已确定的各等级策略梯度执行（具体限制阈值待定义） |
| **E** | 健康度最低 | 适当放宽执行限制，优先保障核心问题治理 |

## 2. 已确认的评估方式

仓库健康度等级由以下两路评估结果共同合成：

### 2.1 模型评估（LLM 随机抽样评估）

- **随机抽样评分**：参照提示词（Prompts）中定义的评分方法，对当前仓库随机抽取的代码片段或文件进行质量评分。
- **提示词工程统一维护**：具体的评估要求、评分方法和适用范围由提示词工程模块统一维护。
- **参与综合定级**：模型评估产出的分数作为其中一路输入，参与仓库最终健康度等级的合成。

### 2.2 内置算法评估（internal 确定性评估）

- **确定性逻辑评分**：按照代码实现的静态分析与内置算法逻辑，对目标代码进行确定性的量化评分。
- **关键路径与叶子分支抽样**：定向抽取代码库的入口模块（Entrypoints）以及不同末端叶子节点（Leaf Nodes）的功能分支作为评估对象。
- **参与综合定级**：internal 评估产出的分数作为另一路输入，参与仓库最终健康度等级的合成。

### 2.3 综合分级

- **双路评分合成**：综合“模型评估”与“internal 评估”两路得分，计算得出仓库最终的 A–E 健康度等级。
- **过程数据完整留存**：完整保留两路评分各自的原始结果、抽样明细及实际评估覆盖范围。
- **待标定参数**：两路评分的合成权重、各维度分数范围以及 A–E 五个等级的具体分数分界线待进一步确定。

## 3. 补充设计建议（待确认）

以下条目作为待确认的系统设计建议记录：

### 3.1 评分契约与执行策略

- **出口层统一契约**：在各评估功能的出口层定义统一的评分结果契约；功能内部的 AST 解析、协议通信、文件读取及辅助计算仅负责向所属功能提供基础事实。
- **评分元数据完备**：每一项评分结果均保留评价维度、评分标准版本、支撑证据、执行状态和适用范围。
- **定级与用级版本锁定**：执行仓库分级评估时使用固定版本的评分标准；其他功能在本次执行前锁定所采用的仓库等级及对应限制配置，新生成的仓库等级从后续执行开始生效。
- **原始分数口径不变**：将“评分标准”与“按等级调整的执行限制”分开记录。在代码事实和评分标准版本相同的前提下，仅改变仓库等级时，计算出的原始分数必须保持一致。

### 3.2 抽样机制与覆盖范围

- **模型抽样可复现**：模型抽样完整记录候选样本集合、随机种子（Random Seed）、实际抽中样本及对应的源码快照。
- **多维分层抽样**：抽样支持按编程语言、前端框架、业务模块和代码规模分层（具体抽样单位、样本数量及比例待确定）。
- **internal 抽样规则固定**：internal 抽样固定入口识别规则、功能分支选择规则、排序规则及去重方式；叶子节点按功能调用关系定义（具体末端功能单元及识别方式待确定）。
- **覆盖范围随附参与定级**：抽样结果需明确标注实际覆盖范围，样本评分连同覆盖度信息一并参与综合分级计算。

### 3.3 缺失、失效与降级处理

- **无等级时回退默认策略**：当仓库没有可用的分级结果时，其他功能自动使用通用默认限制策略，并在结果中记录实际采用的策略。
- **异常状态分类记录**：对模型不可用、分析能力不足、有效样本不足和源码解析失败等情况分别记录；未完成的评估必须保留当前状态与具体原因。
- **单路有效时的临时策略**：完整的综合分级要求两路评分均满足有效性条件；仅有一路评分有效时的临时结果使用策略待确定。
- **结果缓存与代码变更失效**：分级结果需绑定仓库版本（Commit SHA）、输入摘要及评分标准版本；仓库代码变化后的历史结果复用条件与失效重评规则待确定。
- **质量指标跟踪**：单次抽样评估的覆盖程度、模型多次评分的稳定性，以及 internal 确定性计算的可复现性需分别记录。

### 3.4 语言与框架专项继承

- **定义通用入口**：抽样、评分、双路合成及等级限制策略均先定义跨语言的通用入口。
- **遵循统一契约**：特定语言和框架的专项实现必须遵守通用入口签名及统一的评分结果契约。
- **缺项回退与提交校验**：专项实现缺项时自动回退使用通用实现；专项对外公开入口的范围受提交前（pre-commit）继承校验机制约束。

## 5. 建议验收标准

- **双路结果全链路可追溯**：模型与 internal 两路结果均可完整追溯所使用的评分方法、抽样样本、仓库快照和支撑证据。
- **internal 评估结果确定**：在相同代码输入、相同规则版本和相同抽样配置下，多次运行 internal 抽样与评分的结果完全一致。
- **模型抽样过程可复现**：给定相同随机种子与候选集合，模型抽样结果可复现，且模型调用版本、提示词输入及实际评分结果均被完整记录。
- **原始评分不受等级影响**：验证同一份代码在不同仓库等级（A–E）策略下计算出的原始评分保持统一口径，且能查看当前实际采用的下游执行限制。
- **分级缺失或失效安全回退**：当仓库分级结果缺失或失效时，下游功能能够正确回退并执行约定的默认限制策略。
- **状态可辨识且等级合法**：无效或未完成的评估具备明确的可识别状态；有效产出的仓库等级严格限定在 `A`、`B`、`C`、`D`、`E` 范围内。
- **专项继承校验通过**：通用与各语言/框架专项功能的缺项回退、公开入口范围及返回结果契约均通过仓库继承校验。
