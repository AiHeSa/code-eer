# 作用域与复杂度按代码位置加权

## 1. 背景与已确认功能

在评估代码的**作用域（S）**与**复杂度（C）**时，同样的代码结构特征处于不同的**代码位置**中，其合理性与风险影响并不相同：

- 例如，末端**叶子函数（Leaf）**直接承担具体业务逻辑，通常不需要强制包裹为纯函数或立即执行函数（IIFE）；
- 而**公共模块（Public）、入口节点（Entry）、全局作用域（Global）或中间承接层（Intermediate）**一旦出现共享可变状态、高复杂度或大范围影响链路，则会带来更高的维护与扩散风险。

因此，系统已确认支持以下核心能力：

- **按代码位置调整有效评分**：同一项作用域属性或复杂度表现，处于公共模块、业务入口、中间承接层或末端叶子节点等不同位置时，根据位置权重配置产生不同的有效评分贡献与汇总占比。
- **建立跨维度加权映射**：在作用域（S）、复杂度（C）与代码位置上下文之间建立显式的加权关系，支持按代码位置灵活配置各项指标的加权规则。

实现时需明确区分以下四个概念层次，避免混淆：

1. **代码位置上下文（Position Context）**：代码所处的模块属性与调用链角色（如公共模块、业务模块、入口节点、全局作用域、中间承接层、末端叶子节点）。
2. **作用域评分内容（Scope, S）**：局部/全局变量、纯函数、立即执行函数（IIFE）、临时变量属性，以及改动引发的影响链路。
3. **复杂度评分内容（Complexity, C）**：时间复杂度、空间复杂度、循环与递归结构，以及死循环、内存泄漏等严重问题。
4. **全局三项合成权重（Global Synthesis Weights）**：将 S、C、P 三项最终合成为总分时的顶层固定比例（如 45% / 40% / 15%）。仅靠调整顶层合成比例，无法表达“特定作用域或复杂度特征在特定代码位置下要求更严或更宽”的细粒度关系。

## 2. 设计衔接与约束

- **保留基础事实与未加权基础分**：同时保存源码基础事实、未加权的基础分（Baseline），以及经代码位置加权后的有效分；每次计算均记录所依据的位置上下文、节点角色、加权规则及策略版本。
- **位置角色加权与 P 维度分值解耦**：用于对 S/C 加权的“代码位置角色上下文”与“代码位置维度自身的职责适配得分（P 的分值）”分开记录；系统按代码所处的位置角色对 S/C 进行加权，而不是把 P 的分值直接乘到 S/C 上。
- **只调整权重贡献，不重复扣分**：位置加权仅用于放大或缩小既有作用域/复杂度特征的扣分系数与汇总权重，绝不对同一个代码质量问题重复记账扣分。
- **候选或未知位置角色的透明降级**：当代码节点的位置角色仅处于“候选”或“未知”状态时，明确记录权重选择受限；若采用回退策略，须由策略配置显式声明并保留原因。
- **严重问题不被位置权重稀释**：对于死循环、内存泄漏等已确认的严重问题，其高权重扣分与总分封顶约束必须优先保障，严禁因普通位置权重折算而稀释或抵消严重风险。
- **双路评估契约一致且独立于仓库等级**：内置算法评估（internal）与模型评估（LLM）共用同一套位置上下文定义与加权契约；原始评分（含位置加权后的有效分）不随仓库 A–E 健康度等级的变化而改变。

## 3. 核心设计决策与 v1 实验实现

当前实验策略（`scoring-policy-v1`）已完成以下六个核心模块的首版设计与落地实现，详细矩阵与计算公式见[位置加权设计](../../technical-designs/2026-11-07/position-weighting.md)：

| 设计模块 | 解决的核心问题 | 当前 v1 实验策略实现（`scoring-policy-v1`） |
| --- | --- | --- |
| **权重矩阵配置** | 不同位置角色在 S、C 及汇总时的权重系数如何设定 | 区分末端叶子（`leaf`）与严格位置（中间承接 `intermediate`、全局 `global`、入口 `entry`、公共 `public`）；严格位置的扣分系数与汇总重要性均高于叶子节点 |
| **加权生效层级** | 位置权重作用于维度整体还是具体子项 | **叶子节点**的有效作用域（S）仅评估调用影响链路深度，不因未写成纯函数或 IIFE 扣分（仍正常评估复杂度 C 与严重风险）；**严格位置**保留完整作用域封装要求，并放大 S/C 普通问题扣分与汇总重要性 |
| **数值计算方式** | 位置加权公式、封顶约束与总分合成如何衔接 | 基于未加权基础分与位置系数计算有效分；死循环与内存泄漏的严重扣分及封顶值不乘位置系数，直接向上传播封顶；三项总分仍按 `0.45S + 0.40C + 0.15P` 合成 |
| **多重角色处理** | 同一函数或文件兼具多个位置角色时如何取值 | 当同一对象同时命中多个角色（如既是入口又是公共或全局）时，按“从严原则”取各项系数的最大值，不将多个系数连乘 |
| **位置未知回退** | 静态证据不足以唯一确定位置角色时如何处理 | 当存在未解析调用或仅具备结构级事实导致角色未知时，对所有候选位置配置计算分数上下界（数值包络区间），并保持 `partial`（部分完成）状态，不伪造确定分数 |
| **参数标定与验证** | 如何验证权重合理性并校准参数 | 已建立覆盖多角色、未知调用、带副作用叶子及严重封顶传播的集成测试；具体权重参数后续将继续结合人工样本与权重敏感性实验进行标定 |

## 4. 验收方向

- **位置变化驱动有效分变化**：固定相同的作用域或复杂度源码事实，仅改变其所处的代码位置上下文（如从末端叶子移至核心公共入口），系统能严格按照权重配置产出预期的有效分变化。
- **基础事实与未加权基础分不丢失**：切换不同位置权重配置时，底层源码事实与未加权的基础分始终保持不变且完整可追溯，不会被加权结果覆盖。
- **与 P 维度职责评分去重隔离**：同一质量问题在 S/C 中的位置加权计算，与 P 维度自身的职责适配判定各自保留独立依据，不发生重复扣分。
- **多角色与未知角色确定可复现**：针对多重角色并存、位置角色未知以及触发回退策略的场景，其角色优先级选择、分数区间计算与最终结果均清晰可查、确定可复现。
- **策略版本严格隔离**：位置权重的调整通过发布新策略版本生效；历史评估记录依然绑定并保留执行时的原策略版本与原始结果。
