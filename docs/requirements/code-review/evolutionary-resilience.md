## 1. 第一性原理与核心价值导向

好代码的本质不是静态截面的“防御完备”或“形式教条”，而是同时最小化**机器运行风险**、**人类/AI 认知负荷**与**随时间演进的变更爆炸半径**。围绕这一本质，确立三项核心导向：

1. **演化韧性优先（防止急性劣化）**：评判代码的核心标尺是“团队或模型顺着当前模式继续迭代 N 次后，代码是否会发生急性劣化（分支爆炸、状态传染、散弹式修改、复杂度失控）”。
2. **边界严守契约，内部信任且快速失败（降低防御性编程权重）**：大多数内部代码在既定契约下开发。只在入口层（Entry）做外部输入校验与窄化；内部调用链（Intermediate / Leaf）直接信任契约，拒绝冗余判空、静默吞错或伪造兜底默认值，避免拦截并掩盖本该立即暴露的契约违例（Fail-Fast）。
3. **最小作用链路与先例对齐（反对假性扩展的过度设计）**：能在单作用域、单函数、单文件内闭环解决的问题，绝不以“预留未来扩展性”为借口无故拉长跨文件、跨模块调用链路；新增实现必须优先对齐仓库既有同类功能的实现粒度与组织先例。

## 2. 四类典型急性劣化模式

| 劣化模式 | 初始截面表征 | 顺延迭代后的急性劣化后果 | 核心归因维度 |
| --- | --- | --- | --- |
| **分支爆炸型** | 新增硬编码条件分支或布尔标志参数 | 多重条件组合嵌套，每次新增场景均需修改核心控制流 | 复杂度（C）/ 演化扩展性 |
| **状态传染型** | 在模块顶层或共享上下文新增可变状态 | 多处函数隐式读写同一状态，形成强时序耦合与状态污染 | 作用域（S）/ 状态传播 `W` |
| **散弹修改型** | 业务规则内联散落，或无视先例盲目跨文件拆分 | 单一需求变更被迫跨多文件同步修改，漏改即产生缺陷 | 作用域链路（`F/U/L`）/ 位置（P） |
| **隐式成本失控型** | 循环或高频路径内隐藏高开销调用或对象分配 | 数据规模增长或外层再套循环时，触发非线性性能雪崩 | 复杂度（C）/ 时间与空间增长阶 |

## 3. 修订后的好代码五维支柱

将第一性原理映射为五个按优先级排列的核心支柱，明确区分静态可证明事实（Internal）与语义/演化推演（LLM）：

| 优先级与支柱 | 核心要求 | Internal 静态证明重心 | LLM 语义与推演重心 |
| --- | --- | --- | --- |
| **1. 演化韧性与抗劣化** | 分支收敛、概念内聚、签名抗膨胀、拒绝过度抽象 | 分支增长斜率、参数个数、跨文件散度变化 | 顺延迭代 3 次的劣化推演、是否存在更短更优实现链路 |
| **2. 局部性与影响隔离** | 作用域与生命期最小化、共享可变状态零容忍 | 词法作用域、纯度/IIFE/临时变量、影响链路 `M/F/U/L/W` | 局部封装是否真正隔离变化，状态流转是否破坏局部性 |
| **3. 架构位置与职责纯粹** | 入口窄化校验、内部 Fail-Fast、编排与叶子解耦 | 拓扑角色、模块依赖方向、内部冗余判空与空 `catch` 检测 | 区分合理边界防御与掩盖 Bug 的过度防御，评估职责纯度 |
| **4. 执行成本透明度** | 增长阶受控、显式预算对齐、死循环与泄漏熔断 | 跨调用链时间/空间成本上界、无界循环与资源未释放证据 | 结合业务数据规模推断无显式预算时的复杂度风险 |
| **5. 认知直白度** | 扁平控制流、名实一致、遵循仓库既有先例与惯用法 | 函数/文件行数、最大嵌套深度、读写副作用与命名前缀匹配 | 命名领域贴合度、是否违背仓库既有同类实现的惯例模式 |

## 4. 双阶段应用模型：编码前预防与编码后审阅

围绕 AI 辅助编码与代码审查闭环，好代码标准分为两个阶段落地（具体信号矩阵见[设计文档](../../technical-designs/2026-11-07/anti-degradation-signals.md)）：

### 4.1 编码前预防指导（Pre-Coding Preventive Constraints）

在模型开始编写代码前（通过 Skills / Rules 注入），重点约束**代码组织方式与边界纪律**：
- **先看先例再动手**：先检索仓库中同类功能的实现位置与文件粒度，遵循既有模式。
- **最小链路优先**：优先在最小作用域（局部块 → 函数 → 单文件 → 同模块）内闭环，无明确当前需求不得跨文件新建抽象层。
- **边界防御、内部直通**：仅在模块入口校验外部输入；内部函数信任类型契约，禁止防御性吞错或无依据兜底。
- **隔离变化点**：将易变分支抽离为数据映射或独立纯函数，不在主干控制流上堆叠条件分支或共享可变状态。

### 4.2 编码后增量劣化审阅（Post-Coding Delta & Optimality Review）

在一轮代码编写结束后的审阅阶段，核心切入点不是孤立看新代码，而是**基于修改前后快照（Before / After Delta）评估劣化斜率与链路最优性**：
- **存量方法复杂度放大率（`ΔC`）**：既有函数是否因为本次追加逻辑而出现嵌套加深、分支膨胀或时间/空间增长阶跃迁。
- **存量变量与函数的作用链路增长（`ΔS`）**：既有局部状态是否被提升为共享状态，受影响的方法数（`ΔM`）、文件数（`ΔF`）、模块数（`ΔU`）、链路深度（`ΔL`）与状态传播（`ΔW`）是否被异常拉长。
- **最小更优链路审计（Minimal-Link Optimality）**：审视本次新增的跨函数、跨文件或跨模块调用是否必要——是否存在完全等价但作用链路更短（如单文件内闭环、复用既有结构）的更优实现。
