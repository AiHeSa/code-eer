## 1. 本轮目标

将已有的 AST 静态提取证据与三项评估算法（作用域、复杂度、代码位置）串联起来，构建一套**全链路可追溯、确定可复现**的量化评分系统。

- **服务调用方式**：评分核心引擎通过编程接口（API）供后台服务直接调用，本轮暂不扩展 CLI 命令行与前端界面。
- **覆盖评分范围**：包含**作用域（S）**、**复杂度（C）**、**代码位置（P）**三项独立维度评分，以及由三者合成的**三项综合分**。

## 2. 系统必需行为

- **四级结果与源码快照绑定**：按“代码对象（变量/函数） → 文件 → 模块 → 仓库”四个层级分别保留评分结果与明确的聚合单元；所有支撑证据均绑定对应的源码快照，确保不脱离原始代码上下文。
- **四层推导严格分层**：将“原始语法事实”、“语义推导结论”、“规则命中判定”和“最终数值映射”分为四个独立层次；仅凭语法特征识别出的候选项，绝不自动当成已证实的语义结论。
- **规则执行记录完备**：每一项评估规则均完整保留执行状态、适用性判定、结论、源码证据、所依赖的前提假设，以及尚未满足的前置条件。
- **未知与异常状态如实表达**：严格区分“未知（`unknown`）”、“不支持（`unsupported`）”、“执行失败（`failed`）”和“不适用（`not_applicable`）”；绝不将未知项静默折算成满分、零分或直接视为检查通过。
- **多维配置独立版本化**：评估规则、计分参数、性能成本预算、架构职责契约以及多级聚合策略，均实行独立的版本号管理。
- **双路来源追溯与证据去重**：内置算法评估（internal）与模型评估（LLM）的结果各自保留来源标识；同一评估维度按来源策略合成，并对两路评估中重叠引用的同一源码证据明确归属与去重规则。
- **原始评分与仓库等级解耦**：仓库健康度等级（A–E）仅用于选择下游执行时的限制策略，不会反向改变本次评估的原始评分标准。
- **严重问题独立封顶约束**：对已确认的死循环、内存泄漏等严重问题设置独立的扣分与封顶约束，并在结果中同时保留“未加封顶前的原始合成值”与“施加严重问题约束后的最终值”。
- **支持按代码位置条件加权**：作用域（S）与复杂度（C）的有效评分支持结合代码位置上下文进行加权，并完整保留未加权基础分、加权后的有效贡献及所采用的位置权重配置，详见 [REQ-SCP-002](position-conditioned-weighting.md)。

### 诚实计分与防伪造原则

- **实验状态显式标注**：当前候选计分数值以实验策略运行，尚未完成人工样本质量标定；所有产出结果均显式标注 `experimental` 状态，未知项绝不会被强行填成确定分数。
- **拒绝粗略指标替代**：系统严格遵守证据边界，绝不为了凑出表面数字而采用失真的替代逻辑——例如：**不用循环嵌套层数代替真实时间复杂度**、**不用目录名称代替模块架构职责**、**不在缺少跨文件分析时把“当前文件内零引用”当成“改动无外部影响”**。
