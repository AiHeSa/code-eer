## 1. 已确认的功能范围

基于 AST 解析结果、变量与函数的声明/引用位置及其影响范围，分别计算**作用域（Scope, S）**、**复杂度（Complexity, C）**、**代码位置（Placement, P）**三项独立评分，并合成为综合质量评分。

| 评分维度 | 核心评估内容 |
| --- | --- |
| **作用域（S）** | 纯函数、立即执行函数（IIFE）、局部变量、全局变量、临时变量，以及改动引发的影响链路（受影响的方法、文件及整体链路长度） |
| **复杂度（C）** | 时间复杂度与空间复杂度（重点参考循环结构、递归调用及内存占用行为） |
| **代码位置（P）** | 按功能模块边界区分公共文件与业务文件，并结合入口节点、中间处理、叶子节点等角色评估职责适配度 |

系统同时保留 S、C、P 三项原始评分与最终合成的综合评分。

### 已确认的核心评分规则

1. **作用域“基础分 + 属性百分比加成 + 链路调整”**：作用域基础分按“局部”与“全局”两档确定；纯函数、立即执行、临时性等属性按基础分的百分比进行加成，再结合影响链路长度形成综合的作用域评分。
2. **常规复杂度“时间优先”**：在常规复杂度评分中，时间复杂度的权重高于空间复杂度。
3. **严重问题高权重扣分**：针对死循环（Infinite Loop）与内存泄漏（Memory Leak）两类高危问题，采用专门的高权重严重问题规则，大幅提高对应问题的扣分占比。
4. **代码复用统一归入影响链路计量**：代码被多处复用所产生的影响范围，统一纳入“作用域影响链路”指标计量，不得在代码位置或其他维度因被复用次数多而重复加分或扣分。
5. **结合代码位置进行条件加权**：作用域（S）与复杂度（C）的实际生效评分需结合代码所处的位置上下文进行加权（同一作用域属性或复杂度表现在不同代码位置上具有不同的权重），具体要求详见 [REQ-SCP-002](position-conditioned-weighting.md)。

## 2. 评估对象与属性建模建议（待确认）

以下内容为待进一步确认的系统设计建议：

- **评估对象粒度**：基本评估对象涵盖变量、函数与类方法；每个对象均记录其声明位置、引用位置及所属功能模块。
- **作用域层级与可组合属性**：作用域范围划分为块级（Block）、函数级（Function）、模块级（Module）与全局级（Global）；“纯度（Purity）”、“立即执行（IIFE）”与“临时性（Temporality）”作为可叠加组合的附加属性。
- **纯函数判定状态**：纯函数评估结果区分为“已验证”、“条件成立”或“未知”，并保留判定所依赖的外部调用与状态假设。
- **立即执行函数（IIFE）记录项**：记录其闭包变量捕获、对外部共享状态的修改、返回值逃逸情况及异步执行行为。
- **临时变量记录项**：记录变量的实际生存期、引用范围及是否发生逃逸；局部变量可同时具有“临时变量”属性。
- **跨作用域共享状态细分**：分别记录模块级变量、进程级全局变量以及对象实例上的共享可变状态。
- **评估单元边界**：函数或方法以“函数体 + 约定的调用传播范围”作为评估单元；变量的计算范围需明确到初始化点、更新点与使用点。
- **统一汇总口径**：不同粒度的评估对象均保留各自的评估单元标识与规则适用性说明，向上汇总（对象 → 文件 → 模块 → 仓库）时按同一口径执行。

## 3. 三项维度评估细则建议（待确认）

### 3.1 作用域（Scope, S）

- **影响范围多维评估**：综合声明可见性、实际引用、读写行为、共享状态修改、闭包捕获、引用别名（Alias）和逃逸行为评估影响范围。
- **直接与传递影响统计**：分别统计并记录直接影响与传递影响的方法数、文件数、模块数，以及最长影响链路长度。
- **依赖方向与改动影响分离**：入站依赖（被谁调用）与出站调用（调用了谁）分别记录；静态依赖可达范围与特定代码改动推导出的实际波及范围分别记录。
- **代码修改场景对比**：修改场景区分声明签名变更、内部实现变更、状态读写变更与导出接口变更，并绑定修改前后的源码快照。
- **作用域得分计算**：由“局部/全局基础分 + 有效属性百分比加成 + 影响链路调整”共同形成作用域分（具体基础分数值与链路扣分映射待标定）。
- **复用链路去重**：代码复用通过调用与引用关系进入影响链路，直接与传递调用方、受影响文件及模块均按唯一稳定标识去重。
- **属性加成与复用广度解耦**：纯函数与状态隔离作为正向属性加成的依据，而代码被复用的广度则交由影响链路指标客观计量。
- **静态分析边界标注**：动态调用、外部未知消费者及超出分析边界的引用，明确保留为“未解析（unresolved）”状态。

### 3.2 复杂度（Complexity, C）

- **时间与空间独立子评分**：时间复杂度和空间复杂度分别产出子评分；输入规模使用具名符号变量表示（如记录数 `n`、图边数 `m`）。
- **权重分配与严重问题单列**：常规场景下时间权重高于空间；死循环与内存泄漏分别单独记录高权重扣分贡献及源码证据。
- **执行结构特征记录**：提取并记录循环边界、顺序连续执行与多层嵌套循环、递归分支数、递归深度、缓存（Memoization）使用及函数调用次数。
- **空间占用分类列示**：空间复杂度重点记录峰值辅助空间（含递归调用栈开销），并将输入空间、输出空间与中间辅助空间分别列示。
- **评估结论与前提留存**：每次复杂度评估均保留最终复杂度结论、成立前提条件、源码证据以及未知项。
- **严重问题分级判定**：死循环与内存泄漏区分“已证实”、“疑似”与“未知”。其中，死循环结合退出条件、取消信号及常驻任务生命周期契约综合判断；内存泄漏结合对象存活周期与资源释放责任综合判断。
- **结合任务规模与成本预算评分**：复杂度评分结合预期任务规模、算法职责和已声明的性能成本预算，分别列示渐近增长阶（Big-O）、具体执行成本与预算符合度（时间与空间预算、增长阶到分数的映射及缺少预算时的默认评分规则待确定）。

### 3.3 代码位置（Placement, P）

- **模块边界与调用角色识别**：以功能模块为边界，识别代码在调用链中的角色——包括**入口节点（Entrypoint）**、**编排层（Orchestration）**、**中间处理（Intermediate）**与**叶子节点（Leaf）**，并支持同一代码单元兼具多种角色。
- **公共与业务职责区分**：在文件层面区分“公共基础能力”与“业务实现”，并将代码的实际被共享范围与其声明所属模块独立记录。
- **角色职责适配度评估**：结合代码所处角色评估其职责适配程度——例如：入口节点是否聚焦契约校验与流程编排、公共模块是否保持清晰的共享边界、叶子节点是否保持纯粹的局部功能职责。
- **多源位置证据融合**：综合目录结构、文件/符号命名、项目配置、导出关系及调用关系提取位置证据；当静态关系不足以唯一确定角色时，保留候选角色列表。
- **三项维度职责正交**：代码位置（P）维度专注于按“职责适配程度”评分；至于改动影响范围大小与算法执行开销，则分别交由作用域（S）和复杂度（C）维度计分。

## 4. 综合评分与系统集成建议

- **分值区间与方向**：S、C、P 三项评分及综合评分均采用 `0–100` 分制，分数越高表示对应维度的代码质量越好。
- **首版建议权重**：
  - 综合评分默认权重建议：**作用域（S）45%**、**复杂度（C）40%**、**代码位置（P）15%**。
  - 常规复杂度内部权重建议：**时间复杂度 60%**、**空间复杂度 40%**（死循环与内存泄漏等严重问题的高权重规则单独配置）。
- **策略版本化与样本校准**：权重配置、各项评分规则和适用条件统一实行版本化管理，具体参数经代表性代码样例校准后确定。
- **缺失与不适用项处理**：生成完整综合分要求核心必需项有效；缺失、未知及不适用项分别记录，并在综合结果中保留整体有效性状态。
- **与仓库分级解耦**：在相同源码事实、规则和配置下，计算出的原始评分保持一致；仓库 A–E 健康度等级仅用于选择下游执行限制。
- **双路评估契约一致**：内置算法评估（internal）与提示词工程评估（Prompt）使用相同的维度标识和证据格式约定，并各自保留评分来源。
- **语言与框架专项继承**：由通用能力定义标准入口，各语言和框架专项实现继承通用契约；专项缺项按通用能力回退处理，并保留能力覆盖情况记录。

## 6. 建议验收标准

- **作用域基础事实提取**：变量同名遮蔽（Shadowing）、闭包捕获、变量逃逸、全局状态读写及对象属性修改均能提取出准确的源码证据。
- **IIFE 与纯函数行为验证**：立即执行函数的外部状态修改、纯函数的外部非纯调用，以及存在未解析依赖时的纯度降级判定均符合预期。
- **作用域计分可追溯**：同一评估对象的多项有效属性按基础分正确计算百分比加成，输出结果完整保留基础分、属性加成明细、影响链路调整值及封顶信息。
- **影响链路去重与边界**：受影响的方法、文件与模块均正确去重；循环依赖、相互递归组、超长链路截断及未解析调用关系均可在结果中清晰查看。
- **代码复用不重复计分**：同一代码复用关系在影响链路中归属明确，代码位置（P）及属性加成项不会因被复用次数而再次重复加分或扣分。
- **复杂度表达式验证**：固定次数循环、顺序连续循环、不同输入规模的多层嵌套循环及递归调用，均能生成对应的成本表达式并通过验证。
- **空间占用归属清晰**：递归调用栈开销、缓存占用及输出数据规模在空间复杂度分析中各自归属明确。
- **严重复杂度问题与防重**：常规复杂度评分保持时间权重高于空间；死循环与内存泄漏严格按高权重严重问题规则触发扣分，且同一份源码证据不会在常规项与严重项之间重复扣分。
- **常驻循环与受控缓存区分**：合法的服务端常驻事件循环、终止性未知的复杂循环、预期内的受控缓存与已证实的内存泄漏，均能产出各自对应的判定结论与证据。
- **位置职责判定准确**：公共模块叶子节点与业务模块入口节点分别按各自的职责契约评估；当调用关系不完整时，候选叶子节点保留关系覆盖度状态。
- **综合分全链路可解释**：综合评分可向下追溯至 S、C、P 三项得分及各子项贡献；未知项与不适用项均按既定策略显式处理。
- **跨等级一致性与继承校验**：同一源码的原始评分在不同仓库健康度等级（A–E）下保持一致；通用能力与各语言专项实现均通过仓库继承校验。
