## 本次交付

- 新增 scoring 内部服务，执行实验参数的 S/C/P 映射、区间传播、按所有权分层聚合。
- 实现规则/分数/报告 Schema、规则依赖排序、去重所有权、严重扣分和综合约束。
- 实现来源融合函数、来源一致性与分歧检查，默认运行 internal，不伪造模型来源或正式等级。
- 基于 AST 增加直接跨文件函数链接、调用图 SCC/压缩链路、原始类型操作子集的纯度/成本证明。
- 根据明确模块配置检查静态依赖；职责规则依赖显式角色契约与可证明的行为。
- 固定工作区源码清单及内容摘要，评估期间变化或取消时不发布完成报告。
- 保存 report.json、evidence.json，包含派生依赖位置和成本模型，验证全部证据引用可追溯。
- 接入 POST /v1/assessments，并更新已部署的本地后台服务；没有新增 CLI。

## 验证

- 构建、类型检查和能力继承校验通过。
- 101 项相关集成测试通过；验证算术、去重、区间、风险、来源、真实 AST、HTTP、快照及失败文件保留。
- 完整前提样例得到 S=54、C=100、P=100、internal 综合 79.30；缺少前提时保留 partial。
- 当前工作区评估的 26290 条规则证据引用均能在原始或派生证据中解析。
- 改动文件/函数长度检查通过；完整多语言长度检查仍受缺少 Java Runtime 限制。

## 当前仓库结果

149 个源码文件中成功解析 142 个，7 个 Java/Rust 文件因环境未就绪而未解析，并保留在评分分母中。
生成 3996 个评分对象和 16646 条规则/资格判定；210 条已判定静态模块依赖规则的条件分为 100，确认违例为 0。
完整 S/C/P 和综合分保持待定，原因包括未配置真实任务预算/职责、更多语义证明缺失及部分语言环境未就绪。
实验参数尚未人工标定，报告区间不表示质量点估计，不生成正式 A–E 等级。

更多循环/递归成本、别名/逃逸和框架语义证明继续保留为后续能力，不将结构候选直接转换成确定分数。
