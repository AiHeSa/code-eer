# 运行时与运行后增量劣化审阅

## purpose
在一轮编码完成或提交前，基于修改前后快照差分（Before / After Delta）与目标语言/框架特征，以最小 Token 开销识别急性劣化信号并给出最小作用链路重构方案。

## inputs
检查模式（runtime 或 postrun，默认 postrun）、前后快照与 diff、本地差分指标、AST 目标特征及可选的注入记录。独立调用时重建上下文，不假定已执行注入。

## budget
审阅过程遵循“过程静默、静态预筛、异常才唤醒”的低干扰边界：
1. 模型处于连续编码与调试主循环中时不主动打断。
2. 本地预筛逐规则返回 triggered、clear 或 unknown。只有全部适用候选证据完整且为 clear，无延后项、覆盖限制或配置错误时才能静默结束；仅表示本次预筛未命中风险。
3. 缺基线、解析失败、未解析调用、触发器不支持或超时均不得当作 clear；进入定向复核或保留 partial，必要时返回一句限制说明。
4. 深度语义审阅可由支持隔离执行且已获任务授权的适配器分发；否则在当前审阅上下文处理，不要求宿主一定具备子代理能力。

## dispatch
依据 `../contracts/context.md` 与 `../contracts/resolution.md` 按异常信号精准分发：
1. 比对 `../routing/catalog.json` 中通用规则的 `checkTrigger` 与当前增量差分（如存量复杂度放大 $\Delta C$、作用链路增长 $\Delta F / \Delta L / \Delta W$、入度为 1 的跨文件导出、内部防御分支）。
2. 只读取顶层目录映射到当前语言／框架的目标索引，比对其中规则文件族的 checkTrigger。
3. triggered 加载 applicability、check 与 evidence；unknown 定向补证或记录未决；clear 只保留预筛记录。
4. runtime 在一轮编辑结束后处理受影响对象；postrun 核对约定范围的全部候选与遗留项。源码、目标或规则版本改变时，使相关旧结论失效。

## execute
按已选规则的 check 步骤核对证据和例外；预筛信号是审阅候选，不能直接定性为违例。
只输出审阅结论与建议；实际修改遵循当前任务授权，修改后重新绑定快照和验证。
本文件是编排源；预筛器与 Harness 适配尚未接入，不声称已有自动检查能力。

## output
按 `../contracts/results.md` 输出确认的违例、证据及精简建议；存在未知或延后项时保留 partial 并说明必要限制。
完整账本在接入本地评估器后外置存储；未加载、未检查或预筛 clear 的规则不能伪装成语义验证已满足。
