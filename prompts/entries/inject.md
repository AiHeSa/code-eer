# 运行前极简约束注入

## purpose
在开始编码或确定修改范围前，按当前任务涉及的通用维度与目标语言/框架，合成最小 Token 体积的高杠杆预防约束，从源头遏制假性扩展与过度防御。

## inputs
任务目标、计划修改范围、仓库同类功能先例、目标语言与框架标识；缺失项标记为未知，不假定默认跨文件架构。

## budget
前置注入遵循极简注意力预算：
1. 路由解析、继承合并与阶段投影在构建期或本地工具内完成，不让主会话模型逐个读取路由表与契约文件。
2. 通用基线约束控制在 200 Tokens 以内，目标附加预算由适配器显式配置；未命中的目标规则不得进入上下文。
3. 条件、例外与约束作为完整单元计入预算；无法容纳时延后该规则并记录 partial，不能截掉前提。

## dispatch
依据 `../contracts/context.md` 与 `../contracts/resolution.md` 执行两级分发：
1. 从 `../routing/catalog.json` 选取 `phase=inject` 的通用规则，并按当前对象合并同目录 `xx.<target>.md` 专项覆盖。
2. 仅打开目录映射到当前目标的路由，按规范化路径去重后选取规则文件族；专项必须关联同目录通用根文件。
3. 先判断 applicability，将必要条件、例外与 inject 一起投影；适用性未知时保留条件式要求，不输出无条件禁令。

## execute
仅合并已选规则的有效投影，保持原有强制程度与例外，不在入口新增具体质量要求。
优先处理前置依赖，再按目录顺序选择完整规则单元；记录去重、未知及预算延后项。
本文件是编排源，由构建器适配为自包含 Skill；源分发说明本身不是宿主 Hook，自动调用与 Token 预算计量仍待实现。

## output
按 `../contracts/results.md` 生成精简前置约束清单；内部覆盖记录与规则 ID 留存备查，不在主对话中打印冗长元流程账本。
